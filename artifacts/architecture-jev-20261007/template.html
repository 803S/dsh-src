Jev 在项目中的位置

独立决策服务的本地适配层。输入是任务、真实请求或有限候选，输出是校验后的结构化分类。风险分类会被宿主执行策略消费；分工与技能是建议。

实际执行权在哪里

在 Manager → Broker → Ledger → transport。范围、冻结内容、硬边界、人工命令来源、额度和结果锁共同决定是否发送。Jev 不持有发送工具。

02 · Jev 内部架构

四项产品职责，对应五种 taskType；风险包括单笔与整批计划

@@SVG:jev@@

单笔正文上限 65,536 字节，审查 state 上限 1 MiB；默认超时 120 秒，可配 1–300 秒。风险不使用跨请求缓存；无供应商自动重试或切换。confidence 用于审计，不是安全概率。图中“allow”仍须经过宿主硬边界与执行检查。

03 · 一笔请求如何经过 Jev

当前托管出口主路径；扫描计划复用 Broker，但整批评估一次

@@SVG:risk@@

前置条件与回读并非因 GET/HEAD 就可信；自动及人工路径共用检查并可独立调用 Jev。扫描审批不逐笔重新调用模型，但出口逐笔匹配冻结清单、次数与速率。具体执行还会检查取消信号、会话生命周期及 scope 版本。

04 · 审批与恢复生命周期

流程示意；区分任务授权、单次发送、UI 执行状态

@@SVG:approval@@

人工等待没有默认过期时间；有界执行期限从实际启动/发送开始。已发送而结果未知不会自动重放，也不宣称 exactly-once。allow-read 只适用于宿主允许的单笔未知影响确认入口，不能用自报 read/compute 覆盖 Jev 已判定高危。

职责与模式矩阵

以下为当前代码能力，不推断本机配置是否开启。

职责taskType实际调用位置适用会话输出与权限

风险 · 扫描scan-plan有界计划提交 → Broker → advisor主、子会话均可整体评估；逐笔执行靠冻结计划、配额与硬检查

开关如何影响行为

模式行为阅读边界
总开关 disabled不调用 Jev（显式合成 probe 除外）设置保留；默认 disabled，不代表本机实际启用状态。
risk = on允许宿主消费 Jev 的低风险结论还须范围、请求硬边界、归属、配额、安全材料等全部通过。
risk = shadow允许评估但不提供托管自动授权旧 httpDecisionPolicy 返回 legacy-rules；托管 allowsLowImpact 明确要求 on。
risk = off / 服务失败没有有效 Jev 低风险授权托管路径挂人工；旧 HTTP 分支按原规则。
delegate / skill = shadow只评估与记录不把建议作为 on 模式提示交给主模型。

关键边界与当前接线状态

  • 两条 HTTP 路径：受控上下文存在时，src_http 在 Manager 分支直接返回；后面的 httpDecisionPolicy 是仍保留的非托管分支。不能把两者画成每笔请求连续经过的双重 Jev 审核。
  • 风险审查不是漏洞定级：Jev 识别本次验证的实际副作用；漏洞成立与严重度由证据准入、研究数据和主/复核代理流程处理。
  • 文件测试例外：新测试文件及已验证自有测试文件有受限自动路径。后者需精确 URL、强 ETag / If-Match、账户和 scope/credential 版本等宿主证据；自称“自己的资源”不够。
  • 浏览器两层能力：Browser 出站适配有生产代码；Jev runBrowserLoop 目前只定位到模块与测试。设置页的 browser 选项不等于快速循环已在生产调用。
  • Laya 历史命名：laya-client.js、历史环境变量及 telemetry 字段保留，但 Jev 主调用点导入 jev-client.js。不存在已证实的 Jev 失败后自动回退 Laya 链路。
  • 配置与数据隔离：全局 Jev 设置独立于目标会话 infra、领域数据删除和会话投影。原目标请求凭据在本地注入，发送给 Jev 的审查材料会脱敏；冻结原请求存 Ledger 密文。
  • 浏览器置信度与风险置信度不同：技能提示有 0.6 消费阈值；风险策略没有附加“0.9 才安全”的阈值。不能将 confidence 当作经过校准的安全概率。
  • 观察范围：本说明依据当前工作区源码与静态调用搜索；没有启动 DSH、连接 Jev、访问目标、读取运行凭据或重新验证生产部署。测试文件只作为调用与边界的佐证，不等于本次重新跑过全部业务测试。

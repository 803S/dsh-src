## 4. 当前Jev问题：先修接线，不要先怪准确率

### 4.1 新bash守卫绕过Jev，直接请求人工

文件：`lib/src/bash-guard.js`、`lib/src.js`中的`tools/pre-execute`。

当前：匹配到curl写方法/上传/扫描器等信号，直接返回`{kind:'ask'}`。**没有调用Jev。** 默认flag为ask，部分注释仍称shadow。

离线已复现（仅函数调用，未执行命令）：

| 文本 | 当前结果 | 问题 |
|---|---|---|
| `nuclei -version` | ask | 查版本并未扫描 |
| `printf "curl -X DELETE https://fixture.invalid/item"` | ask | 只是打印文本 |
| `curl -X POST https://fixture.invalid/search -d "q=test"` | ask | 未判断搜索实际语义 |
| `curl -X GET https://fixture.invalid/search -d "q=test"` | 按隐式POST ask | 未正确考虑显式方法 |
| `python fixture.py` | 静态allow | 未读取脚本；不代表下游出口放行 |

宿主allowed-once与后面的egress broker没有共享操作决定，可能二次挂审。现有ToolRuntime测试使用fake shell计数，不能证明真实bash＋代理＋Jev＋结果返回贯通。

**要求：关键词成为候选信号，不直接挂人工；由统一操作评估消费。不要简单把guard设off来交差。**

### 4.2 HTTP出口仍实际使用Jev，配置没有关闭

本轮读取非敏感设置：enabled=true，riskMode=on，model=jev-latest，timeoutMs=120000。没有实时调用Jev，不能给准确率结论。

`broker.js`先assess，结合scope/预算等执行条件决定active或pending。并非“Jev只能建议、不能放行”。拦住等待人工与永久拒绝应区分，Jev不应替代用户授权范围判断。

### 4.3 Jev输入缺完整操作

`egress/advisor.js`主要提交HTTP method/url/headers/body、plan.purpose和verifiedTestObjects。没有统一提交exec中的完整命令、脚本正文和理由。

代理claim进入`manager.authorize`时丢失上层操作上下文；缺理由使用“单笔目标请求，完整内容由出口捕获；需审核实际语义”。Burp的purpose被替换成工具名、摘要等通道说明。

离线捕获advisor参数确认：exec内即便有command和justification，decide入参仍不含它们。

### 4.4 代码把操作类别映射为风险

`decision/jev-client.js`让Jev选择effect/objectClass，代码再把普通write/destructive/external映射high，只对测试文件开例外。自有测试账号没有等价对象模型。

必须区分动作与影响，不能Jev正确识别“修改资料”，代码却因write一律人工。输入补齐与判定契约必须一起改；也不要简单把所有write映射low。

### 4.5 现有限制需诚实表达

`review-input.js`强制fatal UTF-8及64KiB限制，二进制上传可能unreviewable-input；这不是Jev判断文件高危。

可疑命令字符串是信息，不一定含全部行为：脚本依赖文件、变量、运行时返回、远程MCP实现都可能缺失。拿不齐要说明缺什么，不编造依据，不追求静态证明任意程序绝对安全。

## 5. 实施次序：先能产出，再做大整理

### 第一批：打通研究与证据读取（最高产出价值）

#### A. 公开漏洞资料通道

现有web_search可访问固定搜索入口，web_fetch NVD等会受目标范围阻断。提供资料只读路径，不要求把NVD当成测试资产。

实现约束：
- 复用web_fetch/现有公共查询路径，不新增浏览器或常驻服务。
- 区分“公共资料阅读”与“目标主动测试”；不将资料域自动加入scope。
- HTTPS、只读GET、禁止携带目标认证头/请求正文；公共地址校验及重定向逐跳核对。
- 首批覆盖可信CVE记录、公告等可解释资料来源；可配置扩展策略，不硬编码某个目标的漏洞答案。
- 响应有界，明确来源URL、状态、内容截断/分页；不执行下载的代码或网页脚本。
- 无结果、搜索服务故障、资料不可达分别呈现，不当作漏洞不存在。

验收：隔离fixture中从产品版本查到资料，取得受影响版本/利用前提/引用，再形成验证假设；同时测试重定向到本机、外带凭据、越界主动请求均不获授权。

#### B. 审批结果直接可消费

文件：`egress/notifications.js`、`manager.js`、`tools/index.js`证据读取。

- executed回注必须携approvalId、实际方法/URL（安全展示）、responseEvidenceId/结果引用、状态与下一步读取方式。
- `src_get_evidence`支持从approvalId查对应结果；旧记录可按该审批真实task/dispatch精确关联，不能按最近ID/相似URL猜。
- 未保存正文/压缩体仅hash应诚实显示；现有证据可读不应再要求用户补包。
- 保留原工具的输出，不把“Burp返回了多少字节”当完整响应。

验收：批准一个请求→读取同一响应→验证结果落research；0次重发目标、0次询问用户补包、0次猜observation编号。结果未知保持未知。

#### C. 研究质量基准

增加一个可复现、隔离的贯通基准，至少包括：
- 指纹→公开CVE公告→版本前提核对→基线与差分→实际证据→复核。
- 一个不受影响版本/错误前提的负例，不能因版本字符串或404乱报。
- 一项受阻时继续独立分支；证据到手后正确续接。

先用确定性合成工具/公告证明项目链路，再做一次有预算上限的真实主模型/Jev测试。没有真实模型测试就不要宣称“挖洞能力提升已证实”。不以漏洞数量KPI逼模型造finding。

### 第二批：统一Jev操作评估，减少人工打扰

复用现有broker、store、宿主工具生命周期，不新增第二套审批平台。

统一输入至少包含：

```
operationId / sessionId / intentId
用户授权目标、账号/测试对象说明及来源
主模型操作理由（标记为模型解释）
工具名、原始参数、命令、cwd
引用的脚本/文件内容或类型感知摘要＋版本/hash
预期请求/实际冻结请求、次数/速率/累计规模
当前缺失信息
```

实现要点：
1. 在工具执行前捕获上下文；同一operation贯穿代理/原生MCP/结果回注。并发不得使用“session最近命令”猜归属。
2. 候选风险信号交Jev，不把关键词写成最终结论；纯本地打印/版本查询正例必须通过。
3. Jev输出区分实际影响、允许/待人工、信息缺失和理由；服务/解析错误单列，不伪装高危。
4. 单一operation的决定在入口和出口共享。执行层检查范围、原文、脚本版本、预算一致，不重新审批同一语义；动态新动作另有明确关联。
5. 人工批准后不再强迫模型编安全材料；已有明确前置条件仍需按批准内容验证，变化时解释实际原因。
6. 不允许理由“无害”覆盖相反原文，也不以方法或工具名定危害。
7. 自有测试账号/文件的判断依据来自用户声明和真实对象记录，不要求所有站点都支持ETag；影响其他对象、费用、共享数据时仍需说明。
8. 远程MCP明确信任边界：本机proxy不能保证远端内部行为，不承诺统一网络隔离已解决所有问题。

验收：同一低影响操作经src_http/curl/脚本/Burp结论一致；最多一张审批；查看版本、打印命令、测试小文件上传、自有可丢弃账号资料修改正常；未知/真实生产影响/原文被改分别正确处理。记录真实Jev误拦率，而不是只验证mock allow。

### 第三批：用户协助真正续接，不再复制审批

文件：`lib/src.js`的src-todo、`store.js`、`tools/index.js`、ActionCenter。

- 完成/放弃先由可信用户命令持久化，再投递followup；不能仅告诉模型“请再调用工具改状态”。
- 回注携todoId、intentId、目标入口、用户备注和后续动作。完成只是输入就绪，不是漏洞已验证。
- 放弃：撤销依赖该输入的分支或写覆盖限制，继续独立方向；不反复挂同一项。
- 投递失败可见且支持重投，不重复写入/重复发目标请求。入队不冒充模型已执行。
- 账号待办必须给实证完整入口、角色/数量、操作步骤；没找到注册入口就明确说明，不造/register。
- 去重不能只用title.includes(approvalId)：approval-1和approval-10会误匹配，detail里的重复会漏。关联operation/审批目的去重；真实账号协助可以引用审批背景，不能因此一律禁止。
- 历史重复待办不静默删除；先提供可审查整理结果。

验收：完成/放弃命令调用后store即正确；通知失败状态可见；登录完成后实际读取/导入/验证；不存在ID无新行；已有审批不再建立同目的todo。

# local.118：只读误拦与不可执行审批修复

## 已确认的原因及修复

1. 旧硬闸把所有含 forward 的头一律视为方法改写。现在合法 IP 格式的 `X-Forwarded-For` / `X-Real-IP` 交由 Jev 判断实际影响；方法覆写、转发目标/Host 改写和编码歧义不自动放行。这不是按 GET 方法无条件放行。
2. 旧只读单被冻成 `safety:null`，点击批准必报 `SRC_GATE_SAFETY_PLAN_REQUIRED`。现在只有用户明确批准时，宿主验证原始加密冻结请求、当前范围、单次预算、未执行状态和原 Jev read/compute + low/allow 判定，才补齐只读执行材料。事务保持原审批 ID、请求、预算、拒绝和资源阻断不变。启动、查看和等待不会自动发包；重复点击不重放。
3. 空 PUT 不能保证不会替换/清空资源，仍待审。缺材料的卡片禁用批准，说明需由 AI 补齐材料，仍可拒绝；不会用备注绕过写前备份和前后核验。
4. 报文由已冻结的脱敏请求格式化为 HTTP 请求行、Host、请求头和正文。标明并非 Burp 抓包，不恢复凭据，也不对外调用 Burp。来源 IP 探测与空 PUT 有简短具体说明。
5. 扫描的三处 `error.code?.startsWith` 在 DOMException 数字 code 上会二次抛错；已改为类型判断。回归还发现直连传输包装取消/闸异常为网络错误，已保留原始控制流。planned 收官警告改为更新真实状态，不再强制委派。

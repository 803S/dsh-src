# local.123：审批链再次审查与修复

## 发现与修改

1. **高危判定与安全说明不一致。** 原流程只验证安全说明存在，Jev 已判删除/写入/外发时，自报 `compute` 或 `read` 仍能在用户批准后执行，且无前置校验和回读。隔离复现确认后，在批准、补料以及重启后的未发送授权恢复中统一核验；失败发生在写入“已授权”状态之前。高危单仍可拒绝。
2. **前置检查与回读漏掉语义核验。** GET/HEAD 的形式不证明没有副作用。复用现有 Jev 和有界队列，批准前逐个核验新增的检查请求，只有明确低影响读取/计算才能作为检查执行。相同检查仅判定一次；普通单笔请求不会新增调用。正常删除仍经过真实快照、前置比对、原始发送及回读，测试确认可执行。
3. **已发送异常仍可能声明未发送。** 主机执行路径现在根据主操作是否已进入发送阶段设置错误状态；发送后的证据/响应失败报告结果未知，保持禁止重放。
4. **给模型的未知审批提示仍要求补材料。** 符合人类低影响确认条件的冻结单笔请求明确提示用户确认实际报文，不再要求为读取/计算虚构备份。已识别写入与删除仍要求相应材料。

本轮复用现有执行器、Jev、审批记录和队列，无新增依赖、数据库表或后台服务。测试日志、会话数据、截图和发行包放仓库外，保留原有 artifacts 目录。

# 异步审批修复与项目复核（2026-10-06）

## 交付边界

本次修复针对 SRC 对目标资产的外发审批，不扩展本地普通文件权限管控，不改供应商配置。沿用现有 Jev、SQLite 控制账本、审批卡、原生命令和执行器；无新增运行时依赖、数据库表或常驻服务。

本次发布版本为 `0.1.0-local.111`；实际部署、推送和发行状态见本文末尾的交付记录。旧版只存摘要、未保存原请求的审批不能凭空恢复；不得从脱敏摘要重建正文。

## 原因与修复

| 问题 | 原因 | 本次处理 |
|---|---|---|
| Jev 已判低风险仍反复人工审批 | 自动策略只接受 read，POST 一刀切 veto，安全说明又强制进入人工通道 | read 与 compute 同样走低风险判断；单笔询问真实请求语义，复合计划支持纯计算；危险/未知不放松 |
| 用户过一阵批准就过期 | 把人工等待复用为请求/扫描的执行时长 | 待审无默认期限；执行窗口从工具实际启动/首次领取发送权开始，等待不消耗预算 |
| 重启丢审批 | 原请求、Burp 回调和审批绑定只有内存，启动撤销全部任务 | 原参数认证加密存入现有 manifest；跨重启恢复原编号、原摘要和原额度，次数及启动状态不重置 |
| 真正重启 DSH 无法开盘 | pending_approvals 的 method schema 未包含已使用的 TASK/SCOPE | 补齐合法枚举，新增真实 schema 往返与 DSH 跨进程验收；不是仅重建 manager |
| 一项待审后会话停止 | 工具说明要求立即结束回合，bash 待审计划提前绑定下一次命令 | 只挂起对应分支；有独立工作就继续。人工批准的 bash 扫描显式用原 taskId 恢复，不抢占独立 bash |
| 同路径读取也被写操作锁住 | resource 锁按路径粗粒度覆盖 | 精确拒绝/未知请求仍阻断；Jev 明确允许的独立只读请求及审批单内的辅助检查不被路径锁连带拦截 |
| 安全说明与实际执行不一致 | 读取/计算分支丢弃显式前后检查 | 非空检查必须合法且真实执行；前提不符不发主请求，验证不确定则隔离且不重试；空对象只表示未声明检查 |
| 待办写入失败留下无编号锁 | 账本和 UI 存储之间缺少恢复绑定 | 持久审批编号、并发发布去重；发布中断或补材料中断后恢复同一冻结任务，不新拼正文 |
| 复合审核可能外泄嵌套原文 | 只脱敏 entries，hostExecution 留有 base64 副本 | 复用全计划脱敏投影，所有嵌套请求统一处理，增加负例测试 |

最新用户日志中 `POST /render` 的正文是 `{"template":"{{7*7}}"}`。旧逻辑将其转成人工；模型随后重新提请求时遗漏正文，产生第二单，半小时后两单批准均失败。本次不是扩大 TTL，也不是放开所有 POST，而是修正自动分类、冻结内容与等待生命周期。

## 执行语义

```text
模型提交真实请求/有限计划
          │
     范围与协议检查
          │
     Jev + 硬边界
     ┌────┴─────┐
明确低风险       高危 / 未知
自动执行         加密持久待办，无默认过期
                 │ 同时继续独立工作
                 │ 用户几天后处理仍是原单
                 ▼
           核对真实范围/来源/安全前提
                 │
           原请求只领取一次执行权
                 │
           记录实际结果并通知模型
```

- 人工待审不是长连接等待，不占 Jev 队列、curl 连接或正在运行的工具。
- 扫描的数量、速率及执行时长仍有限；恢复不能扩大预算，已经启动的扫描不能靠重启获得新额度。
- 结果未知、人工拒绝、真实范围/凭据版本变化、工具来源变化、授权删除，不能靠重新询问 Jev 或换工具绕过。
- 网络无法保证目标服务器“恰好执行一次”；保证的是本地事务领取、不盲目重发及未知结果诚实记录。
- Burp 正常重启后通过真实用户命令上下文恢复同来源原生工具，执行冻结参数；不将 Burp 改为 HTTP，也不恢复任意回调。

### 可维护性复核（保留行为的建议）

- **命名，低**（`lib/src/egress/ledger.js:201`）：账本兼容字段 implicitRead/completed_read 也用于成功的低风险纯计算。保持兼容，本轮不做纯命名迁移；注释应按“隐式低风险单笔”理解。
- **单一职责/结构清晰度，中**（`lib/src/egress/manager.js:22`）：manager仍同时负责范围、审批适配与发送生命周期，继承了既有大模块；不再额外拆多层服务，本轮用清晰的持久绑定与执行入口限制状态交叉。
- **重复/DRY，低**（`lib/src/egress/notifications.js:2`、`lib/src/decision/jev-client.js:60`）：待审继续提示及嵌套脱敏已复用；验证器按场景隔离，避免通用断言把不同正常操作误判失败。
- **过度设计/YAGNI，低**（`lib/src/egress/broker.js:25`、`lib/src/egress/frozen-plan.js:6`）：保留现有SQLite manifest与审批UI，删除原内存计划的128项永久容量阻塞；新增加密小模块而非新增存储系统。
- **常量/魔法数字，低**（`lib/src/egress/plan.js:5`、`lib/src/egress/manager.js:54`）：请求上限、速率、执行窗口和临时回调缓存是资源限制，不代表待审TTL。未把无限等待变成无限请求额度。
- **项目约定，低**（`README.md:9`、`scripts/egress-feasibility/managed-run.mjs:38`）：文档中文，原始测试产物仓库外，生产改动和安装包发布分别标明，不把测试通过说成已上线。

上述复核不是对任意未知资产业务语义、Burp手工操作/扩展或操作系统逃逸的绝对安全保证。没有发现本次已覆盖审批链上必须通过新增常驻组件才能解决的问题。

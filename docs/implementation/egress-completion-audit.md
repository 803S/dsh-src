# SRC 出口审批闸：实现与证据核对

日期：2026-10-04（原始验收）；2026-10-05已按用户授权发布local.109，详见 `docs/evaluation/release-local109-20261005/README.md`。下文未部署表述为原验收时状态。本文件区分运行证据与限制；不是“零风险”保证。

## 架构和可信边界

- 一个授权决策中心：manager → broker → SQLite。Jev 审核完整有界清单一次，实际发送按 URL、方法、头、正文、次数、速率、有效期确定性核对。命令名/脚本名从不等于无限流量授权。
- 原生 bash 工具不换名字。版本化最终 spawn 执行器加 macOS 网络约束，覆盖 full-access、Python、子进程、后台任务、能力脚本。SRC 工具入口还校验执行器版本标记，部署漏装/误覆盖时拒绝执行，不静默退回原生未受控出口。
- shell HTTP/HTTPS 经会话专用 mitmproxy；宿主 HTTP 工具经同一 broker 的受控 transport。它们共享授权账本，并非所有宿主 socket 都经过同一物理代理。
- 高危单笔只由用户命令批准、宿主执行不可变请求及安全检查；模型不能批准自己、不能将批准转换成代理写权限。未知结果不自动重试/补偿。
- 重型代理最多4个，空闲且无未消耗的活动任务时约2分钟释放。轻量宿主监听器保留原端口，防止旧子进程借端口复用进入其他会话；最多1024个保留会话端口。请求包不触发重启，只能由实际工具入口重新唤醒。崩溃不自动恢复。
- 本地文件/图片/搜索与能力文档读取只启用禁止网络的文件沙箱，不启动 TLS 代理。保留原生文件策略；控制/配置/执行器文件额外受保护。
- 可信基础包括宿主、系统内核、已安装能力/初始 Skill、用户配置和原生 command/run 用户事件；不是对恶意宿主或同权限任意外部进程的虚拟机级隔离。

## 发送入口审计

`makeHttpFetch` 在实际工具执行 ALS 内调用目标 manager；兼容 TLS 降级分支同样转回 manager，不绕开。src_http、表面扫描、被动/差分/凭据验证、规则页和 survey 的 fetch 注入均经此路径。命令执行能力转入原生受控 shell。能力安装/测试、proof服务、未适配 browser/MCP/PTY/web_fetch 明确拒绝；不以提示词劝模型遵守。

宿主控制流例外：Jev 使用用户私有配置端点；固定公共搜索/证书透明/FOFA接口仅允许明确工具、固定路径和参数形态、认证头白名单、公网DNS及有界预算，不能用作通用URL出口。公共查询计数保留15分钟并有容量上限，不永久累积到不可用。

原始 `proxiedFetch`/legacy standalone API 是宿主库函数，不是模型工具；所有已审计模型可达调用经 wrapper。非SRC上下文仍保留原生行为。未知插件工具默认拒绝。

## 证据存储与维护性

宿主 transport 的出口证据与 src_http 的业务归属证据目前分别保存：前者带 task/dispatch，后者保留 intent/OpenAPI/旧接口契约。不是重发，目标发送计数独立验证。暂不在最后一刻合并这两套输出，避免破坏既有追踪契约。

Clean Code 七维检查（只给行为不变的维护建议，不把它当安全证明）：
- **中／函数与结构**：manager 的创建闭包承担scope、生命周期、审批桥接和单笔执行，超过100行；后续可按现有私有边界拆小模块，保持相同API/测试。
- **中／重复**：两个证据呈现路径及 fixture 构造有重复；可共享脱敏/构造函数，但须保留不同归属契约。
- **低／魔法数字、命名**：容量/等待毫秒值与 `work`/`result` 名称分散；可抽为有单位的常量并细化局部名称。
- **约定/可读性**：既有生成式JS与新增紧凑JS风格不同；格式化须单独进行，避免将安全差异淹没。
- **YAGNI**：端口保留监听器有实际生命周期逃逸防护与测试依据，不应为了少一个本地socket删掉。没有加入VM、容器、另一个审批平台。

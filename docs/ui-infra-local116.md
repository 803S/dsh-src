# local.116：基础服务配置回显与 Jev 已存密钥显示

## 根因与实现

1. `SrcStore.view` 在没有 goal 时只返回基础设施默认值；`getInfra` 已能读到复制/保存的真实值，但 `src-authoritative-state` 重建页面时将其隐藏。修复无目标分支，同样合并已存 infra 覆盖项，不修改源配置。
2. 旧 InfraView 只读 props，沿用后的数据依赖投影事件重新到达；草稿又可能遮住新值，未编辑直接保存会误传空值。新 `InfrastructureView` 使用 `src-infra-status` 只读命令；初次打开、投影更新、保存/恢复默认/沿用后都回读；未编辑的保存按钮禁用，草稿与已保存状态分离。
3. 基础服务拆为网络出站、Burp MCP、测试凭据三组卡片，复用 Jev 页的控件配色和响应式布局。实际输入值与默认值、可复用来源明确标注。自动沿用仍在 `src_add_goal` 触发，打开页面不会偷偷写配置；建目标前可手动沿用。
4. Jev 的显示按钮此前仅切换“新输入 key”的 input type。现在可显示独立只读的已保存 key，不纳入编辑草稿、不在保存其他字段时重发；隐藏、失焦、离页或30秒后收起。仍沿用原用户设置命令，不增加模型工具、不写浏览器存储。

## 安全与兼容

- 未修改真实基础设施、Jev key、范围或审批策略；测试资料均为合成数据。
- 对照账号仍保留 credential:// 引用方式；不会因保存一个字段而重新加密已有引用。
- 只新增一个只读用户命令；原 `/src-infra`、`/src-infra-copy`、自动继承语义不变。
- 不把 placeholder 当已配置、不把保存成功但回读失败写成“保存失败”、不把代理配置存在等同连接可用。
- Burp 的 127.0.0.1 是 dsh 主机回环连接方式，不是远端配置被覆盖。端口与桥路径仍只保存参考；不擅自重写实际 MCP 接线。
- 当前宿主 `recordInput:false` 仅抑制 command/run 输入，并不抑制 command/done 文本；已有 Jev status/save 接口返回 key 的行为未改。本轮不能宣称已存 key 从未出现在宿主历史记录中；密钥显示只在用户设置页，未进一步扩展返回通道。

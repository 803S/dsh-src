# 收录范围确认套路（规则是数据不是闸门）

## 触发场景
读厂商规则/提交范围时发现目标资产类别（海外、App、公益关联主体等）疑似不收录，或发现规则未明确覆盖的灰色资产。

## 标准套路
1. 先把厂商规则抓回来归档（src-rules-scraper），引用原文条款。
2. **测试照常推进**——不要因为「可能不收」就自行放弃或降优先级；误判的代价（漏掉真洞）远大于多测的成本。
3. 同时挂 src_user_todo（kind=decision）请用户拍板：标题写明「疑似不收录：<资产类别>」，详情引用规则原文 + 你的判断。
4. 用户确认继续 → 该线正常升优先级；确认放弃 → 记 fact（stopReason 写用户拍板）再降级，不静默丢弃。
5. 规则没说的资产默认可测；历史驳回案例（如美团海外 App）当作 scope 线索而非禁令。

## 收录标准
任何「规则 vs 行动」冲突的决策点都适用；核心是**拦在提交前交给用户，而不是拦在测试前由 agent 自决**。

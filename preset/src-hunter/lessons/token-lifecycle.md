# 认证态与令牌生命周期：测试环境跳板与低频纪律

## 触发场景
- 目标需登录态才能测越权/业务逻辑，已通过 Burp 抓包或 dork 泄露拿到凭据。
- 发现 `test`/`uat`/`staging`/`pre`/`dev` 前缀子域、内部管理后台、调试端点、源码/.git/sourcemap 暴露。
- 需要验证 token 复用、改密失效、web token 能否打 App/小程序网关。

## token 生命周期验证套路
1. **登出回放**：拿到登录态后，先复现一个需鉴权请求作为基线；再触发登出/改密/会话过期，重放同一请求——仍 200 即会话未失效（中危：登出态可操作）。⚠ 操作顺序警告：登出测试会**弄掉你自己 Burp 里该站点的登录会话**，测前确认这是你自己的测试账号，或先把 Cookie 存成 fact 再登出。
2. **改密后失效**：改密后用旧 token 重放，仍有效即高危（凭据轮换不生效）。⚠ 改密在真实账号上是破坏性操作——**优先用小号，或转 manual-test 移交用户**，不要拿用户主号试。
3. **web token 打 App 网关（出货大户）**：web 端拿到的 Cookie/JWT 常可复用到 App/小程序的 API 网关（同源鉴权、共享 session）。路径：从 web 流量提取 token → 对已知 App 接口（/api/v*、/gw/、移动端专用域名）构造请求 → 能读数据/调接口即越权实锤。这是国内 SRC 高分高频项，主动试。
4. **验证码复用**：同一验证码多次提交有效、或登录态绑定后验证码仍可复用，记 finding（中危起）。

## 测试环境战利品清单（test→prod 跳板）
测试环境不只是「容易挖」，常是**拿到生产钥匙的入口**：
- **源码/.git/sourcemap 泄露**：staging 常开 source map，反推生产接口结构与密钥。
- **调试端点**：actuator/druid/swagger-ui/debug console/env leak，常暴露内部配置与凭据。
- **弱鉴权**：staging 常关闭 WAF、用弱密码/默认账号/无鉴权内部接口。
- **staging 从 prod 抽数**：测试系统上的**真实用户数据**泄露本身就是可收的严重漏洞。

**跳板套路**：测试环境拿到的 token/凭据/接口清单/内部配置，对生产端点做**最小足迹验证**——一次登录 + 一个良性请求证明有效即构成 finding（high+，凭据复用 + 生产可达双证）。

## 红线（白帽纪律 + 噪声纪律）
- **证明即止，禁止囤积**：用自己的测试账号记录或脱敏样本完成证明，**禁止批量导出真实用户数据——哪怕在测试环境**。既是最小化伦理，也是噪声纪律（大流量拉取触发风控，和锁号分析自洽）。
- **跳板后只做证明复用所需的最小动作**：用测试凭据进入生产后，禁止借道深挖或改动任何数据。
- **认 scope**：测试环境是否在授权范围内先查【资产分诊】三分法——明确排除就跳过，沉默/模糊就建非阻塞待办快速确认，别默认在 scope。

## 认证态低频纪律（防锁号=整条管线报废）
- 带认证头请求打的是业务层和风控引擎，**锁号=auth-profile 全失效、coverage 全线 blocked、整个会话残废**——风险远高于未授权探测。
- 低频、分散请求；撞到风控响应（异常 403/429/验证码突增/账号锁定提示）**立即停手**，转 manual-test 或换时段。
- 认证态请求单独计预算，阈值低于未授权流量的一半。
- 改密、批量拉数据等破坏性操作默认转 manual-test，不在自主流里跑。

# 认证态与令牌生命周期：测试环境跳板与低频纪律

## 触发场景
- 目标需登录态才能测越权/业务逻辑，已通过 Burp 抓包或 dork 泄露拿到凭据。
- 发现 `test`/`uat`/`staging`/`pre`/`dev` 前缀子域、内部管理后台、调试端点、源码/.git/sourcemap 暴露。
- 需要验证 token 复用、改密失效、web token 能否打 App/小程序网关。

## token 生命周期验证套路
1. **登出回放**：先复现一个需鉴权请求作基线；触发登出/改密/会话过期后重放——仍 200 即会话未失效（中危）。⚠ 登出会弄掉自己 Burp 的登录会话：确认是自己的测试账号，或先把 Cookie 存成 fact。
2. **改密后失效**：改密后旧 token 仍有效即高危（凭据轮换不生效）。⚠ 改密是破坏性操作——优先小号或转 manual-test，不要拿用户主号试。
3. **web token 打 App 网关（出货大户）**：web 端 Cookie/JWT 常可复用到 App/小程序 API 网关（同源鉴权/共享 session）。web 流量提取 token → 对已知 App 接口（/api/v*、/gw/、移动端专用域名）构造请求 → 能读数据即越权实锤。国内 SRC 高分高频，主动试。
4. **验证码复用**：同一验证码多次提交有效、登录态绑定后仍可复用，记 finding（中危起）。

## 测试环境战利品清单（test→prod 跳板）
- **源码/.git/sourcemap 泄露**：staging 常开 source map，反推生产接口结构与密钥。
- **调试端点**：actuator/druid/swagger-ui/debug console/env leak，常暴露内部配置与凭据。
- **弱鉴权**：staging 常关 WAF、弱密码/默认账号/无鉴权内部接口。
- **staging 从 prod 抽数**：测试系统上的真实用户数据泄露本身可收（严重）。
- **跳板套路**：测试环境拿到的 token/凭据/接口清单对生产端点做最小足迹验证——一次登录+一个良性请求证明有效即构成 finding（high+，凭据复用+生产可达双证）。

## 红线（白帽纪律 + 噪声纪律）
- **证明即止，禁止囤积**：用自己的测试账号或脱敏样本完成证明，禁止批量导出真实用户数据——哪怕在测试环境（既是最小化伦理，也是噪声纪律）。
- **跳板后只做证明复用所需的最小动作**，禁止借道深挖或改动任何数据。
- **认 scope（三分法）**：明确含非生产环境→优先级上调（软目标+生产跳板双重价值）；明确排除→excluded 跳过；沉默/模糊→被动指纹照常做，主动测试前建非阻塞待办快速确认，别默认在 scope。

## 认证态低频纪律（防锁号=整条管线报废）
- 带认证头请求打的是业务层和风控引擎，**锁号=auth-profile 全失效、coverage 全线 blocked**——风险远高于未授权探测。
- 低频分散请求；撞到风控响应（异常 403/429/验证码突增/锁定提示）立即停手，转 manual-test 或换时段。
- 认证态请求单独计预算，阈值低于未授权流量的一半；改密、批量拉数据等破坏性操作默认转 manual-test。

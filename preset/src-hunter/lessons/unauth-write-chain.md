# 未授权写入三步实证与对照打法（Cairn 实证）

## 触发场景
- 发现疑似未授权可达的写接口（增/删/改/导出），需要把「可达」做成可提交的漏洞链。
- 对照报告 16 条发现全靠以下打法拿到 PoC 级证据（未授权可达+PoC 即 low 入库，参照提交质量课程）。

## 三步实证（未授权写入）
1. **未授权写入**：不带认证头构造最小写请求（建一条测试数据/改一个无害字段），确认 2xx。
2. **落库回读**：用读接口/列表接口/导出接口回读刚写入的数据，拿到含新数据 id 或内容的响应——证明写入真实生效且可被读取（比单发写请求强一档）。
3. **删除零残留**：对测试数据执行删除/撤回，再次回读确认消失——既能自证影响面闭环，又不留脏数据（白帽纪律）。

## 配套预检与验证技巧
- **WAF 只读预检**：动手前先 GET 探路（响应头/拦截页/401/429 语义），写请求只对确认可达的面发，避免盲撞风控。
- **本地复刻渲染验证**：XSS/HTML 注入类先在本地复刻目标渲染环境验证 payload 生效，再上目标——减少无效写请求。
- **导出/批量接口单独看**：Excel 导出、日志导出、问卷导出类常是未授权信息泄露的高产面（记 finding 或 concreteLossEvidence 素材）。

## 纪律
写入内容用明显测试标记（如 `poc-<日期>-<随机>`）；删除动作本身就是验证闭环的一部分；全程留 raw 包（写/读/删三段）作 evidence 链。
